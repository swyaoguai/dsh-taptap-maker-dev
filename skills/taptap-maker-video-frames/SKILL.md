# 视频动作帧 → Maker 序列帧素材

适用：手里只有一张静帧，想让角色**动起来**（走、跑、攻击、转圈、挥砍），
并把结果变成 Maker 工程里能直接用的透明序列帧。

## 一、先搞清楚钱和额度（最容易踩的坑）

视频是**按量计费**，不占文本额度。三种 Key 的实情：

| Key / 套餐 | 能否出视频 | 说明 |
|---|---|---|
| M Plan **Go** 档（最低档） | ❌ | 官方明确：Go 档**不含视频模型**。调用视频接口会返回 `1008 / insufficient balance`（v2 是 HTTP 402 `insufficient_balance_error`） |
| M Plan **Explore / Build** 档 | ✅ | 含 H3 视频模型，视频只受**周窗口**限制，不受 5 小时窗口限制 |
| 积分包（1,000 积分 = ¥7） | ✅ | 支持 H3；套餐额度先用，超出部分扣积分 |
| 普通按量计费 Key（`sk-api-…`） | ✅ | 扣账户余额，H3 768P ≈ ¥0.5/秒、2K ≈ ¥0.8/秒 |
| **视频中转站** | ✅ | 你自己的地址 / Key / 模型，不占 Maker 与 MiniMax 额度 |
| **自选本地视频** | ✅ 且免费 | `/taptap-video use <mp4>`，之后抽帧抠像全本地 |

三个经常搞混的点：

1. **MiniMax Code 里每日签到拿的积分 ≠ 平台积分包。** 签到积分（每天 400、
   连续第 4/7 天 1000）只用于 **MiniMax Code 这个应用内**的多模态创作，
   30 天有效；它**不是**开放平台 API 的额度，不能拿来让插件通过 API 出片。
   想用签到积分出视频，只能在 MiniMax Code 应用里做，拿到视频文件后再
   `/taptap-video use <mp4>` 走下面的本地链路。
2. **订阅 Key 和按量 Key 不能混用，但都能打视频接口。** 实测：`sk-cp-…`
   订阅 Key 打 `api.minimaxi.com` 的 v1/v2 视频接口**鉴权是通过的**，
   只是额度为 0 时被 1008 挡住。所以「Gate 住了」不等于「接口不对」。
   插件会按前缀自动识别类型（`sk-cp-` = 订阅、`sk-api-` = 按量），
   **不要再让用户选「Key 类型」**。
3. **不要拿 `mmx quota` 的成功当作「有视频额度」。** Go 档下它直接报
   `no active token plan subscription`。

先跑 `/taptap-video doctor`：它会免费探测鉴权 + 套餐状态 + 三条后端可用性，
把上面这些结论直接翻译成一句话，**不要凭猜测回答用户有没有额度**。

## 一·五、三条后端怎么选

- **中转站**：用户配了就优先用它（`auto` 里排在 MiniMax 前面 —— 配了说明想用）。
  `openai` 协议：`POST /videos` → `GET /videos/{id}` → `GET /videos/{id}/content`；
  首尾帧走 `input_reference`（1 张 = 首帧，2 张 = 首尾帧）。
  字段对不上就切 `generic`，填提交/查询路径 + 响应字段路径；
  报错会点明「哪个字段没取到」，据此改，不要盲试。
- **MiniMax 官方**：有订阅（Explore+）或按量 Key 时用。
- **自选本地视频**：零额度兜底，用 ffprobe 判是不是视频（不看扩展名）。


### 星盘式 /videos 协议的几个硬约束（接中转站时最容易错）

- **Base URL 要带 `/v1`**（`https://xingpan.site/v1`）。只有素材上传 `/reference-assets` 在主机根上、不带 `/v1`。
- **本机图片必须先上传换 url**：data URI / 本机路径 / Base64 都不保证被接受。
- **首帧 / 首尾帧走 `metadata.mode=frames` + `first_frame_url` / `last_frame_url`**，
  不要顺便再发 `image_urls`（首尾帧与普通素材数组互斥）。
- **H3 不能只给尾帧**；Wan 根本不支持首尾帧。这些在本地就该拦住。
- **清晰度由型号决定**，`size` / `resolution` 不能拿来升降档。
- **首尾帧模式下画幅由素材决定**，`ratio` 填了也不保证强制裁切；
  要固定构图先把输入图裁成目标比例。
- **`delivering` 不是完成**：主 status 仍是 in_progress/99%，要等 `delivery_status=ready`。
- 下载要带 Bearer，且只有 HTTP 200 + video/* 才算成片；成片 24 小时过期。

## 二、没有视频额度时的替代做法（按推荐顺序）

1. **在 MiniMax Code 应用里用签到积分生成**（免费），下载 mp4 后导入本管线
   当"自选视频"——抽帧/抠像/合成/导入全本地，零额外费用。
2. **升级到 Explore/Build 档**或买积分包（¥7/1000 积分），同一个订阅 Key
   立刻可用，不用换接口。
3. **换按量计费 Key**，H3 768P 4 秒 ≈ ¥2/条，比整档订阅便宜得多，
   适合"只做几套动作"的场景。
4. **本地 ComfyUI + 开源视频模型**（H3 有官方 ComfyUI 用法文档），
   显存够就完全免费；不强求分辨率。
5. **手上已有现成视频**（录屏、别人给的素材）→ 直接当自选视频导入。

## 三、链路与每一步的验收点

```
首帧（+ 可选尾帧）
  → 提交视频（唯一花钱的一步）
  → 抽帧（本地）
  → 抠像（本地，有逐帧自检报告）
  → 对齐合成整图（本地）
  → 导入 Maker：assets/image/xxx.png + xxx.png.meta + xxx.seq.json
```

### 首 / 尾帧怎么给
- **首帧**：绿幕或纯色背景的全身图最理想；长宽比要在 0.4~2.5 之间、
  最短边 ≥ 256px（插件提交前会自动补边、并提前告警）。
- **尾帧**：**只有 H3 / H3-Max / Hailuo-02 支持**。Hailuo-2.3 带了尾帧会被
  平台判参数错误，插件会提前拦下并告诉你换哪个模型。
- 动作类素材：首尾帧可以给"同一姿势的两个关键点"，让模型补中间过程；
  也可以只给首帧 + 一句"原地走三步，全身入镜，相机固定"。

### 抽帧排法（`--arrange`）
- `uniform`（默认）：等分并取每段中点，**首尾都不碰**。第 0 帧通常是还没动
  的静帧，末帧常是站稳的收尾，取它们会让循环动画卡一下。
- `first-last`：首点 = 0、末点贴结尾。首尾帧模式想"你给的两张都算数"时用，
  代价是循环会顿一下。
- `loop`：首点 = 0，末点 < 时长，专给行走/跑步/待机这类**要无缝循环**的动作。

### 抠像自检怎么读
报告里每帧有 `backgroundFraction`（背景占比）与 `confident`：
- 25%~92% 之间 = 可信；
- 主体只占画面一小块时占比会 > 95%，`confident=false` 是**正确结论**，
  不是 bug —— 真素材里主体一般占 15%~50%；
- 一片 `confident=false` 且占比接近 100%：多半是整帧被抠光或背景与主体同色，
  调 `--tol`（背景容差，默认 40）或换视频，别硬合成。

### 合成为什么"脚底对得齐"
所有帧共用**一个** alpha 包围盒（并集）再贴底放在同一基线，所以角色上下起伏
不会看起来在飘。包围盒**必须在抠完的帧上算** —— 在原帧上算等于没裁
（绿幕也是不透明像素），主体会被缩成一个点，合成图只剩几道细线。
这类"渲染出空图"的 bug 只会在肉眼验收时暴露，所以必须真的打开图看一眼。

### 导入 Maker
- 只把**最后那一张**整图复制进 `assets/image/`：`assets/` 下任何新文件都会被
  Maker 运行时补 `.meta` 并打进构建，中间帧/视频落在那里会变成脏资源。
- 同时写 `同名.seq.json`（列数/行数/每格尺寸/回放帧率/采样时间）。
- 帧数多时自动折成 grid（默认上限 8192px 宽），避免撞纹理上限。
- 回放帧率 = 帧数 / 视频时长（循环）或 ×0.66（非循环，看起来慢一点更清楚）。

## 四、做素材时的实用经验
- 提示词写"**原地**走三步 / 原地转身 / 挥砍一次"，加"相机固定、全身入镜、
  绿幕背景"。加了"向前跑"模型会真的跑出画面，抽帧一半是空的。
- 4 秒 + 12 帧是性价比最高的一档（¥2 左右）；要做 8 帧行走就 4 秒配 8 帧。
- 尾帧给"同一角色的另一个姿势"时，两张图**尺寸与构图要一致**，否则模型会
  参考首帧裁尾帧，动作中途会跳。
- 生成失败或命中安全审核**不扣费**（H3 按成功输出的秒数计）。
