# Game UI / UX

## 信息层级

- 一屏只突出一个主行动；次要信息弱化或折叠。
- 用大小/颜色/位置/留白建立层级，别靠边框堆砌。
- 常驻 HUD 只放“当下必须看”的（血量、关键资源、目标）；其余进菜单。

## 反馈与可见性

- 任何操作都要有即时反馈（高亮、动效、音效）。
- 系统状态可见：加载、冷却、不可用（置灰并给原因）。
- 破坏性操作要二次确认；可撤销优先于确认弹窗。

## 移动端（手游重点）

- 触控热区 ≥ 约 48dp，间距足够，别让按钮贴边贴刘海。
- 尊重**安全区**（刘海/圆角/手势条），重要元素留边距。
- 虚拟摇杆/按钮位置贴合拇指自然区；支持惯用手切换更佳。
- 不要悬停态逻辑（没有鼠标 hover）。

## 可读性 / 可访问性

- 文本与背景足够对比；关键信息别只靠颜色区分（加图标/形状）。
- 字号在目标机型实机可读；长文本可缩放。
- 动效可关（晕动/闪烁敏感）。

## 一致性

- 全局统一配色、字体、圆角、间距、音效语汇——用一套 UI 风格 skill（见 `taptap-maker-ui`）而不是每屏重造。

实机、目标分辨率下验收；注意 NanoVG 分辨率缩放，别写死像素。
